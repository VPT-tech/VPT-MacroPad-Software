# VPT | Pad

Програма налаштування макропада **VPT MacroPad** (9 кнопок + 3 енкодери EC11 на RP2040).

| Шлях | Що це |
|---|---|
| `main.py` | Точка входу (single-instance, трей, журнали аварій у `%APPDATA%`) |
| `main_window.py` | Головне вікно, профілі, синхронізація прив'язок із платою |
| `action_executor.py` | Виконання дій: Tap / Double-Tap / Hold, енкодери, макроси |
| `threads.py` | Фонові потоки: Serial, аудіо-мікшер, активне вікно, WebSocket (YouTube) |
| `widgets.py`, `config.py`, `utils.py`, `updater.py` | UI-віджети, пресети/мапінги, WinAPI-утиліти, оновлення |
| `firmware/VPT_MacroPad/` | Прошивка RP2040 (Arduino-Pico core) |
| `firmware/uf2/` | Зібрана прошивка — можна прошити з програми без Arduino IDE |
| `extension/` | Розширення Chrome/Edge для керування YouTube (див. `extension/README.md`, оновлення в магазині — `extension/CHROME_WEB_STORE.md`) |
| `tests/` | Тести клієнта, хостові тести прошивки, наскрізний тест HW ↔ SW |

## Запуск з вихідників

`pip install -r requirements.txt`, потім подвійний клік по `VPT_Pad.pyw` (без вікна консолі)
або `python main.py`. Закриття вікна ховає програму в трей (значок біля годинника, можливо
під стрілкою ˄); вийти повністю — через меню значка → «Вихід». Журнал роботи:
`%APPDATA%\VPT_Pad.log`.

## Профілі з коробки

| Профіль | Кнопки | Крутилки (обертання / натискання) |
|---|---|---|
| **Медіа** | ⏮ ⏯ ⏭ · Провідник, мут мікрофона, скріншот · згорнути все, диспетчер завдань, блокування | прокрутка / середня кнопка · масштаб / 100% · гучність / мут |
| **NumPad** | 7 8 9 · 4 5 6 · 1 2 3 (як цифровий блок клавіатури) | ← → / 0 (утрим. «.») · ↑ ↓ / Enter (утрим. «+») · гучність / Backspace |
| **Офіс і браузер** | копіювати, вставити, вирізати · скасувати, повторити, зберегти · виділити все, пошук, Alt+Tab | прокрутка / середня кнопка · вкладки ← → / нова вкладка (утрим. закрити) · гучність / мут |

В усіх профілях **утримання нижньої крутилки** — перехід на наступний профіль.
«Налаштування → Відновити стандартні профілі» повертає цей набір.

## Робота без програми

У флеші плати зберігається **профіль для роботи без програми** (за замовчуванням «Медіа»,
змінюється в налаштуваннях). Програма записує його при кожному підключенні, а коли програма
закривається (або зникає) — плата сама повертається до нього. Без програми працює все, що
плата вміє зробити як клавіатура/миша/медіаклавіші; дії, яким потрібен ПК (макроси, мут
мікрофона, гучність окремих програм, перемикання профілів), — лише з програмою.
Нова плата з порожнім флешем одразу працює з вбудованим профілем «Медіа».

## Як розподіляється робота між платою і ПК

Для кожної кнопки/напрямку енкодера програма обчислює специфікацію і надсилає її на плату:
`HID_KEY / HID_MOUSE / HID_MEDIA` — плата виконує дію сама (працює навіть без запущеної програми),
`SERIAL` — плата лише повідомляє подію, а дію виконує ПК (макроси, гучність програм, профілі тощо).
Кнопка, у якої хоч один слот потребує ПК, повністю обробляється ПК.

## Протокол Serial (115200, рядки з `\n`)

ПК → плата: `PING_VPT_MACROPAD`, `PROTO:<n>`, `SET_KEY:<ціль>:<spec>`, `SAVE_EEPROM`, `LOAD_EEPROM`, `RESET_HW`, `ENTER_BOOTLOADER`.
Плата → ПК: `BTN_x_PRESSED/RELEASED`, `ENC_x_SW_PRESSED/RELEASED`, `ENC_x_LEFT/RIGHT`.

**Протокол v2** (прошивка ≥ 1.1.0) вмикається командою `PROTO:2` (відповідь `PROTO_OK:2:FW=<версія>`)
і скидається, коли ПК закриває порт:

* до подій, які плата вже виконала апаратно, додається `:HW` (напр. `BTN_1_PRESSED:HW`);
* при апаратному спрацюванні слоту надсилається `BTN_x_FIRED:TAP|DTAP|HOLD` (для OSD);
* події енкодера несуть множник прискорення `:A1`…`:A5`, виміряний на платі за інтервалом
  між клацаннями (напр. `ENC_1_RIGHT:HW:A3`);
* якщо плату перезапустив апаратний watchdog (зависання > 5 с), перше рукостискання
  після цього містить `:RST=WDT` — програма показує сповіщення.

Тож ПК більше не «вгадує» за своєю копією конфігурації, чи виконала плата дію, і дія не дублюється
та не губиться під час перемикання профілю. Стара прошивка ігнорує `PROTO:2`, і програма
автоматично працює з нею за протоколом v1.

## Надійність

* **Прошивка:** енкодери читаються в перериваннях; апаратний watchdog (5 с); «швидкий» debounce —
  натискання фіксується за ~2 мс, брязкіт контактів гаситься блокуванням на 20 мс.
* **Оновлення:** `.exe` і `.uf2` перевіряються за SHA-256 (поле `digest` asset-а GitHub
  або файл `SHA256SUMS` у релізі) і за розміром; інсталятор перевіряється ще раз безпосередньо
  перед запуском з правами адміністратора. Файл без контрольної суми не встановлюється.
* **WebSocket (YouTube):** сервер на `localhost:8765` приймає лише розширення браузера
  (`chrome-extension://`, `moz-extension://`) і сторінки YouTube — довільний сайт підключитися не може.

## Тести

```bash
# Хостові тести прошивки (моки Arduino API, плата не потрібна)
make -C tests/firmware_sim

# Тести Python-клієнта + наскрізний тест з прошивкою, що працює окремим процесом
pip install -r requirements.txt
QT_QPA_PLATFORM=offscreen pytest tests

# Розширення YouTube: логіка + наскрізний тест у справжньому Chromium (Playwright)
node --test tests/extension/*.test.mjs
node tests/extension/e2e.cjs
```

Наскрізний тест (`tests/test_e2e_hw_sync.py`) запускає справжнє вікно `MacroPadPro` і `SerialThread`,
підключені до прошивки, зібраної під хост, — і для поточної прошивки, і для старої v1.0
(`tests/firmware_sim/legacy/`), щоб гарантувати сумісність з ще не оновленими платами.

## Прошивка плати

Найпростіше — з програми: **Налаштування → Прошити плату з файлу (.uf2)…** і обрати
`firmware/uf2/VPT_MacroPad_v<версія>.uf2`. Програма перевіряє, що це цілісний UF2 для RP2040,
сама переводить плату в режим завантажувача, копіює файл і після перезапуску відновлює
призначення кнопок.

Збірка з вихідників:

```bash
arduino-cli core install rp2040:rp2040   # https://github.com/earlephilhower/arduino-pico
arduino-cli compile --fqbn rp2040:rp2040:rpipico firmware/VPT_MacroPad
```
